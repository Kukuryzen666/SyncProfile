# 📜 История изменений (Changelog)

Все заметные изменения в проекте **SyncProfile** документируются в этом файле с явным разделением по редакциям клиентов (**AyuGram** и **exteraGram**).

## [v10.3.24] - 2026-08-31

### 🚀 Полная поддержка TL_inputMessageEntityCustomEmoji и Java ArrayList в конвертере эмодзи
- **Поддержка `TL_inputMessageEntityCustomEmoji` при отправке**:
  - В методах отправки Telegram использует класс `TL_inputMessageEntityCustomEmoji` со структурой `document.id`, а не плоское поле `document_id`.
  - Добавлен универсальный парсер `_get_entity_doc_id`, который извлекает идентификатор документа как из `TL_messageEntityCustomEmoji`, так и из `TL_inputMessageEntityCustomEmoji` и нативных TLRPC объектов.
- **Безопасная итерация по Java `java.util.ArrayList` в Chaquopy**:
  - Исправлен обход коллекций `entities` при отправке и приёме сообщений: явная поддержка списков через `size()` / `get(i)`, исключающая тихие сбои `TypeError` в Chaquopy на Android.
- **Гарантированное включение Premium для собственного аккаунта**:
  - В `_patch_user_tl_object` добавлен прямой фоллбэк к локальным настройкам слота для собственного аккаунта, обеспечивая активацию выбора и отправки кастомных эмодзи в поле ввода.

### 💬 Исправление отправки кастомных премиум-эмодзи
- **Восстановление регистрации хуков отправки сообщений**:
  - В `on_plugin_load` восстановлена регистрация `add_on_send_message_hook()` и `add_hook` на методы `messages.sendMessage`, `messages.sendMedia`, `messages.sendMultiMedia`, `messages.editMessage`.
  - Премиум-эмодзи при отправке теперь гарантированно преобразуются в `tg://emoji?id=...` для обхода серверных ограничений Telegram для аккаунтов без официальной подписки Telegram Premium.
- **Улучшение алгоритма конвертации `_convert_custom_emojis_to_text_urls`**:
  - Улучшена обработка сущностей кастомных эмодзи в объектах сообщений (поддержка `document_id` как в нативных Java TLRPC объектах, так и в Chaquopy прокси).
  - Восстановлены легковесные хуки на поток обновлений `Updates` для мгновенного отображения кастомных эмодзи во входящих сообщениях.

### 🎯 Восстановление отображения профилей с сохранением 120 FPS через пакетные Put-хуки
- **Решение проблемы отображения профилей из SQLite**:
  - Поскольку Telegram загружает диалоги и пользователей из локальной базы данных SQLite пакетами через методы `MessagesController.putUsers(users, fromCache)` и `putUser(user, fromCache)`, отсутствие перехватов приводило к тому, что локально загруженные пользователи не получали цветов.
  - Внедрены точечные хуки `PutUserHook`, `PutChatHook`, `PutUsersHook`, `PutChatsHook`. Они срабатывают **только один раз при загрузке данных в память**, мгновенно применяя все кастомные цвета, эмодзи-статусы и параметры профиля.
- **Сохранение абсолютной плавности 120 FPS**:
  - Методы чтения `getUser` и `getChat` по-прежнему **вообще не хукаются**. Во время скролла и анимаций не происходит ни одного входа в Python/JNI, обеспечивая максимальную отзывчивость интерфейса.

### ⚡ 100% Native 120 FPS: Полная ликвидация хуков на горячих путях скролла
- **Полное удаление `GetUserHook` и `GetChatHook`**:
  - Полностью исключены любые Xposed/MethodHook перехваты `MessagesController.getUser` и `getChat`, которые вызывались сотни раз за кадр во время прокрутки списков и переключения папок.
  - На устройствах со 120Hz дисплеями и энергоэффективными процессорами (MediaTek Helio G99 / Snapdragon 600/700) время отрисовки кадра теперь занимает 0 мс в Python, обеспечивая идеально плавные 120 FPS без просадок.
- **Прямой In-Memory патчинг коллекций Java (`mc.users` / `mc.chats`)**:
  - При синхронизации и загрузке профилей плагин напрямую обновляет кэшированные в памяти singleton-объекты `TLRPC.User` и `TLRPC.Chat` в `LongSparseArray` Telegram. Все цвета, эмодзи-статусы и премиум-параметры читаются Telegram нативно в чистом Java байткоде.
- **Удаление перехвата глобальных сетевых пакетов Updates**:
  - Из `on_plugin_load` удален перехват `add_hook` на события `Updates`/`UpdateShort`, что полностью сняло постоянную фоновую нагрузку на CPU при получении сетевых событий.
- **Ленивый патчинг входящих MTProto-ответов**:
  - В `post_request_hook` добавлена фоновая обработка `response.users` и `response.chats`, гарантирующая актуальность цветов новых пользователей без перехвата метода `getUser`.

### 🚀 Полное устранение сброса на «Все чаты» и ликвидация фризов при переключении папок/тем
- **Полное выпиливание конфликтующих хуков папок**:
  - Удалены все хуки на `MessagesController.isFilterLocked`, `isDialogFilterLocked`, `areFiltersLocked`.
  - Полностью удален `DialogFilterIsLockedHook` на `MessagesController$DialogFilter`.
  - Полностью удален `DialogsActivityCheckFilterLockedHook` на `DialogsActivity` (он вызывал непредвиденный сброс активной вкладки папок на «Все чаты» при возврате из переписки).
  - Удалена ручная модификация списка `mc.dialogFilters` из `_apply_all_to_all_accounts` — управление лимитами папок полностью отдано нативному Local Premium клиентов.
- **Устранение каскадного 4x умножения JNI-хуков**:
  - Устранена множественная регистрация хуков на 4 перегрузки `getUser` (`long`, `Long`, `int`, `Integer`) и `getChat`, приводившая к каскадному 2–4x кратному вызову Python-рантайма на каждый диалог при скролле и смене папок.
  - Установлен строго один канонический хук на `getUser(long/Long)` и `getChat(long/Long)`.
- **Zero-JNI Fast-Path по `param.args[0]` + кэш `_sp_v`**:
  - В хуках `GetUserHook` и `GetChatHook` проверка принадлежности `uid`/`cid` к базе SyncProfile выполняется **до** вызова `param.getResult()`. Для 99% несохраненных пользователей/чатов возврат происходит за ~10 наносекунд на чистом Python без создания Java-прокси.
  - Внедрен ультрабыстрый прокси-кэш `_sp_v` во все методы патчинга `_patch_user_tl_object`, `_patch_chat_tl_object`, `_patch_full_user_tl_object`, `_patch_full_chat_tl_object`.
- **Устранение утечки памяти и лагов при выходе из тем (Forum Topics)**:
  - Удален тяжелый хук `ChatActivityMenuHook`, удерживавший ссылки на уничтоженные экземпляры `ChatActivity` в Python-памяти и вызывавший тяжелые GC-фризы Android при выходе из темы форума.
  - Исправлена коллизия битовой маски `flags2` (удален ошибочный `flags2 |= 1024`, повреждавший бит `FLAG2_FORUM` у супергрупп).
- **Оптимизация обработки сообщений**:
  - Из `post_request_hook` исключены запросы `messages.getDialogs` и `messages.search`, устранив блокирующий парсинг сообщений на UI-потоке при открытии папок.
  - В конвертере кастомных эмодзи `_convert_text_urls_to_custom_emojis` удалена тяжелая JNI-рефлексия `type(ent).__name__`.

### 🚀 Ликвидация JNI-шторма и фризов при переключении папок и скролле
- **Удаление тяжелых списочных хуков папок диалогов**:
  - Полностью удалены хуки `GetDialogFiltersHook`, `LoadDialogFiltersHook`, `MessagesControllerLockFiltersHook`, `GetDialogFilterHook`, вызывавшие циклический JNI-перебор Java-коллекций (`dfs.get(i)` / `dfs.size()`) на каждый кадр переключения вкладок.
  - Разблокировка папок переведена на легковесные атомарные перехваты (`DialogFilter.isLocked() -> False`, `mc.isFilterLocked(...) -> False`, `DialogsActivity.checkFilterLocked -> False/None`).
- **Отказ от блокирующих пакетных хуков**:
  - Удалены хуки `PutUserHook`, `PutChatHook`, `PutUsersHook`, `PutChatsHook`, синхронно блокировавшие UI-поток при пакетной загрузке сотен диалогов.
  - Внедрён ленивый (JIT) патчинг сущностей строго для видимых на экране 10–15 ячеек через `getUser` и `getChat`.

### ⚡ Внедрение Zero-JNI Fast-Path кэширования (`_sp_v`)
- **Мгновенная проверка кэша Python-прокси (~15 нс)**:
  - При повторных обращениях Telegram к объектам пользователей и чатов во время быстрого скролла проверка выполняется напрямую из памяти CPython без JNI-рефлексии чтения полей (`u.id`).
  - Ликвидирована прослойка `_untracked_uids` / `_untracked_cids`, снижая нагрузку на сборщик мусора (GC).

### 🛠️ Стабильность и оптимизация хуков
- **Строгий фильтр перегрузок методов**:
  - Хуки `getUser`, `getChat`, `getUserFull`, `getChatFull` ограничены условием `num_params == 1`, что исключило двойной перехват внутренних служебных вызовов Telegram.
- **Безопасная обработка `DialogsActivity.checkFilterLocked`**:
  - Добавлена автоматическая проверка типа возвращаемого значения (`boolean` -> `False`, `void` -> `None`), устранившая исключения `IllegalArgumentException` в рантайме Chaquopy.
- **Нативное снятие флага блокировки папок в Java**:
  - При применении профилей сбрасывается бит `FLAG_LOCKED (1 << 0)` в `f.flags`, позволяя `DialogFilter.isLocked()` возвращать `false` нативно без задействования хуков.

- **Снятие локальной блокировки синхронизации**: принудительный сброс флага `_sync_in_progress = False` при ручном нажатии на сброс кэша, исключая отклонение операции фоновыми таймерами.

- **Исправление `_build_peer_color`**: если пользователь установил эмодзи-значок (`bg_emoji_id != 0`, например флаг страны или кастомный премиум-эмодзи), но оставил цвет имени/профиля по умолчанию (`color_id < 0`), плагин больше не отбрасывает объект `TL_peerColor`, а выставляет базовый индекс цвета `color = 0`.

### 🛡️ Устранение вылетов в «Все чаты» и разделение Local Premium
- **Хуки на все перегрузки методов `MessagesController`**: перехват `getUser(long/Long/int/Integer)`, `getChat`, `getUserFull`, `getChatFull`, `putUser`, `putChat`, `putUsers`, `putChats` с регистрацией по полной сигнатуре типов параметров.
- **Разделение логики клиентов**:
  - **AyuGram**: нативный Local Premium управляется исключительно клиентом через `AyuConfig`, плагин не вмешивается в локальные настройки.

- **Исправление битовой маски `TLRPC.User`**: исключён ошибочный бит `flags2 |= 1`, повреждавший десериализацию юзернеймов.

### 🚀 Оптимизация производительности ядра (Core Engine)
- **O(1) проверки типов**: проверки `_is_user` и `_is_chat` переведены на быстрые строковые проверки имени класса, исключая тысячи медленных JNI `hasattr` вызовов при скролле списка диалогов.
- **Быстрый путь в `_patch_user_tl_object`**: исключен синхронный перебор аккаунтов `_get_my_active_uids()` в hot-path.
- **Глобальное кэширование `ExteraConfig`**: класс кэшируется в `_EXTERA_CONFIG_CLASS`, а сохранение настроек выполняется только при реальном изменении.
- **Архитектурная документация**: добавлен файл `BUGS_AND_ARCHITECTURE_GUIDELINES.md` со всеми аспектами, историей багов и инвариантами проекта.

- **Расширение хуков `UserConfig` и `UserObject`**:
  - Методы `UserConfig.isPremium()` и `UserConfig.hasPremiumOnAccounts()` перехвачены для корректной нативной логики табов.

  - Устранено дублирование кнопок ручной загрузки базы. Блок действий сокращён до 3 понятных и взаимоисключающих операций:
    1. **🔄 Синхронизировать с сервером** (`msg_sync`) — быстрая дельта-проверка и загрузка свежих обновлений базы.
    2. **🚀 Опубликовать все аккаунты** (`msg_send`) — мгновенная отправка настроек профилей всех активных аккаунтов на сервер.
    3. **🧹 Сбросить кэш и перекачать базу** (`msg_delete`) — полная очистка локальных кэшей и принудительная загрузка всей базы с нуля.

- **Энергоэффективность и плавность**: отсутствие падений FPS, микрофризов и лишней нагрузки на процессор при быстрой прокрутке чатов и списков диалогов.

## [v10.2.33] - 2026-08-29

### ⚡ Оптимизация производительности

Устранены причины лагов на exteraGram (и частично AyuGram). Все изменения **не затрагивают функционал**.

- **Кэш `_is_user` / `_is_chat` по имени класса**:
  - `hasattr()` на Java-объекте в Chaquopy — это JVM-рефлексия (~10-50µs каждый вызов).
  - При прокрутке RecyclerView `getUser()` вызывается 60fps × N ячеек — каждый проходит через хук.
  - Добавлены `_USER_CLASS_CACHE` / `_CHAT_CLASS_CACHE`: результат определяется **один раз** по имени класса, дальше — dict lookup O(1).

- **Кэш результата патча `_patch_cache`**:
  - `TL_peerColor()` и `TL_emojiStatus()` создавались заново на каждый `getUser()` для каждого пользователя.
  - Теперь: если `(nc, nbg, prc, pbg, em_id, prem)` не изменились — Java-объекты не пересоздаются, `return True` немедленно.
  - Кэш инвалидируется при каждой синхронизации (полной — очищается весь, delta — только изменившиеся uid).

- **TLRPC инициализируется при загрузке плагина**:
  - Убрана проверка `if TLRPC is None: from ...` из hot-path методов.

- **`_video_avatar_uids` — кэш пользователей с видеоаватарами**:
  - Нормализация `photo.has_video` и `photo.flags` выполняется **только один раз** на uid, после чего uid добавляется в set и больше не проверяется.

- **Инкрементальное обновление snapshot при delta-sync**:
  - Вместо `dict(self._profiles_cache)` (полное копирование при 1000+ профилях) используется `_update_snapshot_partial`: обновляются только изменившиеся uid.

- **`_apply_all_to_all_accounts` — background/UI split**:
  - Тяжёлая часть (чтение SharedPreferences, сбор данных аккаунтов, обновление кэша) вынесена в background-поток.
  - На UI-поток отправляется только лёгкий финальный шаг: присвоение готовых значений полям объектов.
