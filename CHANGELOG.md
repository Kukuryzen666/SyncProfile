# 📜 История изменений (Changelog)

Все заметные изменения в проекте **SyncProfile** документируются в этом файле.

---

## [v10.2.35] - 2026-08-30

### ⚡ Масштабная оптимизация производительности (exteraGram & AyuGram)
- **Устранение фризов при скролле (RecyclerView)**:
  - Добавлены кэши `_video_checked_uids` и `_video_checked_chat_ids`. Ранее проверка аватарок вызывала постоянную JVM-рефлексию (`hasattr`, `isEmpty`, `len`) на каждый кадр для всех пользователей без видео. Теперь проверка выполняется строго **один раз** на ID.
  - Добавлены глобальные пулы объектов `_peer_color_cache` и `_emoji_status_cache`, предотвращающие постоянное создание новых Java-объектов (`TL_peerColor`, `TL_emojiStatus`) на каждый вызов `getUser()`.
  - Добавлен **ранний выход (early-exit)** в `_patch_user_tl_object` и `_patch_chat_tl_object`: если объект уже содержит корректные цвета, избыточная повторная инициализация пропускается.

### 🐛 Исправления багов и стабильности
- **Исправлен сброс в папку «Все чаты» и вылеты после АФК**:
  - Полностью исключены проактивные вызовы `mc.getUser()` из UI-потока в `on_delta_applied` и `_apply_all_to_all_accounts`, вызывавшие скрытый `ClassCastException: Long cannot be cast to Integer` в `DialogsActivity.didReceivedNotification` при анимациях переходов.
  - Добавлен безопасный хелпер `_safe_get_user()`.
- **Исправлена очистка кэша**:
  - Действие «Очистить локальный кэш» теперь также сбрасывает кэш чатов и **автоматически запускает фоновую загрузку базы с сервера**, избавляя от необходимости вручную нажимать «Скачать всю БД».
- **Исправлена остановка фонового потока**:
  - `_keep_alive_sync_loop` переведён на `threading.Event.wait(timeout=60)` вместо `time.sleep()`, что обеспечивает мгновенную и чистую выгрузку плагина.
- **Предотвращён `AttributeError` при delta-синхронизации**:
  - Добавлена корректная инициализация `_patch_cache` в `__init__`.

### ✨ Интерфейс и функции
- **Индикатор пользователя SyncProfile**:
  - При переходе на страницу профиля пользователя, использующего SyncProfile, внизу ненавязчиво отображается плашка: `✨ Этот пользователь использует SyncProfile`.
- **Очистка контекстного меню**:
  - Удалены неработающие кнопки «Обновить профиль» и «Инфо о профиле» из меню профиля, вызывавшие ошибки SDK. Пункт копирования Emoji ID сохранён.

## [v10.2.34] - 2026-08-29

### 🚨 Хотфикс v10.2.33

- **Откат `_patch_cache`**: кэш результата патча по uid был некорректным.
  - Причина: Telegram создаёт **новые** Java-объекты при каждом обновлении профиля из сети/БД. Кэш говорил «уже пропатчен» — а новый чистый объект оставался без полей. Результат: никто не получал цвет/статус.
  - Откат: `_patch_cache` и `_patch_version` полностью удалены. Безопасные оптимизации оставлены.
- **Фикс `_video_avatar_uids`**: убрано добавление uid в set при отсутствии фото — это предотвращало нормализацию когда фото появлялось позже.

> Оставшиеся оптимизации из v10.2.33 работают корректно:
> `_USER_CLASS_CACHE`, `_CHAT_CLASS_CACHE`, TLRPC pre-init, `_update_snapshot_partial`, background/UI split в `_apply_all`.

## [v10.2.33] - 2026-08-29

### ⚡ Оптимизация производительности

Устранены причины лагов на exteraGram (и частично AyuGram). Все изменения **не затрагивают функционал**.

- **Кэш `_is_user` / `_is_chat` по имени класса**:
  - `hasattr()` на Java-объекте в Chaquopy — это JVM-рефлексия (~10-50µs каждый вызов).
  - При прокрутке RecyclerView `getUser()` вызывается 60fps × N ячеек — каждый проходит через хук.
  - Добавлены `_USER_CLASS_CACHE` / `_CHAT_CLASS_CACHE`: результат определяется **один раз** по имени класса, дальше — dict lookup O(1).

- **Кэш результата патча `_patch_cache`**:
  - `TL_peerColor()` и `TL_emojiStatus()` создавались заново на каждый `getUser()` для каждого пользователя.
  - Теперь: если `(nc, nbg, prc, pbg, em_id, prem)` не изменились — Java-объекты не пересоздаются, `return True` немедленно.
  - Кэш инвалидируется при каждой синхронизации (полной — очищается весь, delta — только изменившиеся uid).

- **TLRPC инициализируется при загрузке плагина**:
  - Убрана проверка `if TLRPC is None: from ...` из hot-path методов.

- **`_video_avatar_uids` — кэш пользователей с видеоаватарами**:
  - Нормализация `photo.has_video` и `photo.flags` выполняется **только один раз** на uid, после чего uid добавляется в set и больше не проверяется.

- **Инкрементальное обновление snapshot при delta-sync**:
  - Вместо `dict(self._profiles_cache)` (полное копирование при 1000+ профилях) используется `_update_snapshot_partial`: обновляются только изменившиеся uid.

- **`_apply_all_to_all_accounts` — background/UI split**:
  - Тяжёлая часть (чтение SharedPreferences, сбор данных аккаунтов, обновление кэша) вынесена в background-поток.
  - На UI-поток отправляется только лёгкий финальный шаг: присвоение готовых значений полям объектов.

## [v10.2.32] - 2026-08-29

### 🐛 Исправления

- **Некорректные цвета реплаев при 3+ одновременных ответах**:
  - Корень: старый подход использовал глобальный `_active_reply_rgb` — одно поле на весь плагин. RecyclerView рисует несколько ячеек псевдопараллельно: ячейка A ставит свой цвет, ячейка B перезаписывает его, в итоге A рисуется с цветом B.
  - Исправлено: добавлены хуки `MessageObject.getReplyColorId()` и `MessageObject.getReplyColor()`. Каждый вызов получает `thisObject` = конкретный объект сообщения, поэтому нет конкуренции за глобальное состояние.
  - Добавлены вспомогательные методы: `_extract_peer_uid`, `_extract_reply_uid`, `_resolve_color_id_for_user`, `_get_vibrant_color_for_id`.

## [v10.2.31] - 2026-08-29

### 🐛 Исправления

- **Эмодзи-статус не отображался в диалоге пересылки (и в других ячейках)**:
  - Корень бага: Python `int` в Chaquopy при присваивании в Java-поле `long` (а не через аргумент метода) тихо обрезался до `int32` → `document_id` становился `0` → Telegram видел пустой статус и показывал только звёздочку Premium.
  - Исправлено явным приведением через `long(em_id)` во всех четырёх местах создания `TL_emojiStatus` (`_patch_user_tl_object`, `_patch_chat_tl_object`, `_patch_full_chat_tl_object`, `_apply_all_to_all_accounts`).

## [v10.2.30] - 2026-08-29

### 🐛 Исправления

- **Крэш `ClassCastException: Long → Integer`**:
  - В `on_delta_applied` uid теперь явно приводится к `java.lang.Integer` перед вызовом `mc.getUser()`.
  - Ранее Python-int с большими Telegram ID (> 2³¹) сериализовался Chaquopy как `java.lang.Long`, что вызывало крэш в `DialogsActivity.didReceivedNotification` при анимации возврата из чата.
- **Прем эмодзи не отображались в пересланных сообщениях**:
  - Эмодзи-статусы и кастомные эмодзи теперь корректно рендерятся у пользователей, зарегистрированных в SyncProfile.
  - Пользователи **не** из кэша плагина остаются без изменений (`premium` не трогается).
- **Попадание в папку «Все чаты» при переключении чатов**:
  - Устраняется как следствие фикса крэша выше (крэш в `didReceivedNotification` сбрасывал активную вкладку папок в 0).
